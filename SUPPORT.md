# Getting help

**Something is broken:** open an issue in the repository it is broken in. The
bug template asks for the version, the platform and what you expected; those
three answers are what turns a report into a fix.

**Something is unclear:** open an issue too. A question that had to be asked is
a documentation bug, and it gets treated as one.

**You want a feature:** open an issue and describe the problem before the
solution. The shape of the fix is negotiable; the problem is what decides
whether anything happens at all.

**You have a fix already:** send the pull request. See
[CONTRIBUTING.md](CONTRIBUTING.md) — anyone with a GitHub account may open one.

**You found a vulnerability:** do not use any of the above. See
[SECURITY.md](SECURITY.md).

There is no support contract, no chat, and no guaranteed response time. These
are spare-time projects. Issues do get read.
